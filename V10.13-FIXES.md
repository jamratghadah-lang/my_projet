# Jamrat Ghada v10.13 — Fixes

This build applies the requested hardening/fix pass to v10.12.

## Fixed

- AI package knowledge now uses the canonical `packages` field while remaining backward-compatible with legacy `items` data.
- AI package detail no longer falls back to the first package when the requested package is missing.
- Social links no longer duplicate TikTok.
- AI invitation links are generated server-side from private invitation access codes; `eventSlug` is no longer used as an access code.
- RSVP invitation access-code verification moved server-side to `/.netlify/functions/invitation-data`.
- `access_code` removed from public `content/rsvp/*.json` files.
- RSVP and entry-card clients no longer read the invitation access code from public JSON.
- CMS RSVP configuration no longer exposes/writes `access_code` into public JSON.
- AI confirmation and multi-event selection state moved from in-memory Maps to server-side Firestore (`ai_pending_sessions`) so cold starts do not lose state.
- AI-only collections (`ai_conversations`, `ai_leads`, `ai_analytics_daily`, `ai_pending_sessions`) are no longer browser-writable.
- Firestore rules that incorrectly referenced `request.resource` for read/delete were separated into operation-specific rules.
- AI feature-flag lookup now fails closed if Firestore is unavailable.
- Public AI pricing falls back to the canonical `content/pricing.json` only when AI knowledge has not yet been seeded; stale hard-coded package defaults are not used by the AI core.

## Verification performed

- All JavaScript files passed `node --check`.
- Static build command completed successfully.
- Secure invitation endpoint tested with an invalid code (403) and valid code (200).
- Public RSVP JSON files contain no `access_code` field.
